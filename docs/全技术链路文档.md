## 1. 项目是什么

反诈能力实训系统的**前端 + 本地代理**。三个实训模式，AI 能力全部对接腾讯云 ADP 智能体工作流：

| 模式 | 组件 | 用户做什么 | AI 扮演什么 |
|---|---|---|---|
| 模拟来电 | `SimulatedCallModal.tsx` (666 行) | 接一通诈骗电话，用语音或文字周旋 | 扮演诈骗分子，只说台词 |
| 互动剧场 | `InteractiveTheaterModal.tsx` (580 行) | 选剧本背景，做 A/B/C 选择推进剧情 | 扮演主持人，产出剧本 + 选项 + 手册 |
| 反诈问答 | `AntiFraudQAModal.tsx` (217 行) | 问可疑短信/来电/转账指令 | 扮演反诈专家 |

**关键设计决定**：AI 只用 ADP（不接 OpenAI/其他 LLM）。所有外部调用都经本地 Node 代理转发，前端只发相对路径，因此**前端代码里没有任何密钥和外部域名**。

## 5. 外部依赖协议详解

### 5.1 ADP 对话接口（最重要）

#### 端点

```
POST https://adp.gaoxiaobang.com/adp/v2/chat
Content-Type: text/plain        ← 故意不是 json，见下方 CORS
Accept: text/event-stream
```

**必须用域名，不能用 IP。** `adp.gaoxiaobang.com` 解析到的就是 `101.42.184.216`，但这台机器的 nginx 按 `Host` 头做虚拟主机分流：用域名访问才路由到 ADP 应用，直接写 IP 会落到默认 server block 返回 **404**。

> 历史坑：2026-08 时 IP 直连是通的（还没绑域名），代码里写死 IP 能用。后来绑了域名，所有硬编码 IP 的地方全 404。`server.ts` 里现在有注释提醒。

#### 请求体（PascalCase，大小写不能错）

```json
{
  "RequestId": "32-64 位 [a-zA-Z0-9_-]",
  "ConversationId": "32-64 位，同一通电话/同一场问答保持一致",
  "AppKey": "<ADP 应用密钥>",
  "VisitorId": "32-64 位，访客标识",
  "Contents": [{ "Type": "text", "Text": "用户这句话" }],
  "Incremental": true,
  "Stream": "enable"
}
```

#### 为什么用 `text/plain`

该端点 CORS 现状（2026-10-21 实测）：

| 项 | 结果 |
|---|---|
| `OPTIONS` 预检 | **405 Method Not Allowed** |
| `POST` 响应头 | `Access-Control-Allow-Origin: *` |

预检 405 意味着浏览器发 JSON（会触发预检）必被拦。用 `text/plain` 属于 CORS 简单请求，不发预检，而服务端**照常按 JSON 解析 body**。这是必须保留的 hack，`adpClient.ts:122` 和 `server.ts:41` 都有，别"优化"掉。

#### SSE 事件类型（实测抓包）

```
event: request_ack        ← 入参回显，含 Status: success 即表示 Key 有效
event: response.created   ← ExtraInfo.FromName 是命中的 Agent 名，可用于判断路由！
event: response.processing← StatusDesc: "调用工作流"，会反复出现（天然心跳）
event: message.added      ← Message.Type = "thought" 时是思维链
event: content.added      ← 内容占位
event: text.delta         ← 正文增量，Text 字段
event: message.done
event: response.completed
event: error              ← 业务错误，形如 {"Type":"error","Error":{"Code":400,...}}
```

#### 正文可能藏在三种地方（必须全兼容）

| 形态 | 取值位置 | 处理 |
|---|---|---|
| 流式增量 | `evt.Text` | 追加 |
| 整包回复 | `evt.Content`（字符串） | 可能是 `full` 的子串，需去重 |
| 对象型输出 | `evt.Output` / `evt.Payload.Output` | `JSON.stringify` 后交给 `onObject` |

`adpClient.ts` 的累积策略（**改这段前务必读懂**）：

```
1) full 已包含 text        → 跳过（整包重发）
2) text 以 full 开头且更长 → 取 delta 追加（累积式 delta）
3) 其他                    → 直接追加（纯增量 delta）
```

#### 思维链过滤的正确姿势（踩过大坑）

```ts
const isThought = t === "thought" || t === "thinking";
if (isThought) return null;
```

**只按 MessageType/Type 判断，绝不能用"含 Thought 字段"来判断。** 私有化部署会把正文和推理放同一个事件里：

```json
{"Content":"您好，我是XX电商平台客服……","Thought":"[{\"index\":1,...}]"}
```

早期代码写成 `if (evt.Thought) return null`，导致**正文被一起丢掉，前端什么都不显示**。这个 bug 花了一整轮才定位到。

#### 认证错误码

| 码 | 含义 |
|---|---|
| `4505004` | 应用密钥无效。常见原因：环境与密钥不配套（公有云的 key 打私有化端点）、Key 复制不全带空格/换行、应用未发布 |

#### 超时哲学

- 前端 `adpClient.ts`：默认 **180s**（`SimulatedCallModal` 显式传 180000）
- 代理 `server.ts`：**240s**，刻意大于前端 → 正常情况下让前端先超时（前端有友好 UI 提示，裸 504 JSON 难看）

### 5.2 ASR 语音识别

```
POST /proxy/asr  →  http://8.134.117.157:10095/recognition
请求: { "audio_base64": "<纯 base64，不带 data: 前缀>" }
响应: { "code": 0, "text": "识别出的文字" }
```

**录音为什么不用 `MediaRecorder`**：它默认输出 `webm/opus`，队友的 ASR 服务**只收 WAV**。所以 `recorder.ts` 用 `AudioContext` 直接采 PCM 再手写 WAV 头：

- 采样率指定 16000（不支持时回退默认再线性插值重采样）
- 单声道、16bit
- `ScriptProcessor(4096,1,1)`（已废弃但兼容性最好）
- **必须把 processor 连到一个 gain=0 的节点再连 destination**，否则 Chrome 不触发 `onaudioprocess`

**麦克风权限陷阱**：必须 `http://localhost:3000` 打开。`127.0.0.1`、局域网 IP、iframe 预览面板都不行。

### 5.3 TTS 语音合成（Edge 神经网络音色）

```
POST /proxy/tts   { text, voice, rate }
→ audio/mpeg (mp3 二进制)
```

实现在 `edge-tts.js`，**零依赖**，直连微软 `wss://speech.platform.bing.com`：

| 要素 | 值 / 说明 |
|---|---|
| DRM 令牌 | `TRUSTED_TOKEN = '6A5AA1D4EAFF4E9FB37E23D68491D6F4'` |
| 版本伪装 | `CHROMIUM_VER = '143.0.3650.75'`，拼进 `Sec-MS-GEC-Version=1-<ver>` |
| 时间戳签名 | `Sec-MS-GEC` = SHA256(Windows file time + TRUSTED_TOKEN)，**对系统时钟敏感** |
| 时钟校准 | 模块内 `clockSkew` 变量，收到服务端 403 时用返回值修正本地偏差后重试 |
| 免费 | 不需要任何 Key |

6 个中文女声（`audioHelper.ts` 的 `EDGE_VOICE_LABELS`）：`xiaoxiao`（默认）/ `xiaoyi` / `xiaobei` / `xiaoniang` / `xiaohan` / `xiaorou`。

**降级**：`playVoiceSample()` 先试 `/proxy/tts`，失败则 `fallbackBrowserTTS()` 走 `speechSynthesis`。竞态用 `playbackGeneration` 计数解决——旧请求即使晚到也不会盖住新请求的声音。

### 5.4 server.ts 代理层要点

```ts
// 关键中间件：不配这个，text/plain 的 body 会丢
app.use(express.text({ limit: "20mb", type: "text/plain" }));
app.use(express.json({ limit: "20mb" }));
```

三条路由走同一个通用代理循环（`app.all(prefix)`），SSE 靠 `proxyRes.pipe(res)` 流式透传。

**四个已经踩过的坑，改动时不要退回去**：

| 机制 | 为什么必须有 |
|---|---|
| `res.set("X-Accel-Buffering", "no")` | 防反向代理缓冲 SSE，否则流式变成一次性吐 |
| `res.on("close")` → `proxyReq.destroy()` | 前端换场景/关弹窗/超时 abort 后，**上游请求会继续在 ADP 侧跑**。ADP 对同一 ConversationId 是串行的，泄漏的请求会把后续请求堵死 → 表现为"平时很快，连点几次后 200s 无响应 → 504" |
| SSE 心跳（静默 >20s 写 `: keepalive\n\n`） | 工作流跑长 Agent 时上游会长时间无数据，浏览器/中间层可能判定僵死连接 |
| `proxyReq.setTimeout(240000)` | 比前端 180s 大，保证前端先超时 |

### 6.1 模拟来电

```
用户点"接通"
  → buildOpeningPrompt(scenario)          // 见下，措辞很关键

  → sendToADP({ conversationId: 'call-xxx', timeoutMs: 180000 })

  → 结束后 finalText = cleanCallText → extractCallLine（兜底）
  → 泄漏检测：命中 /\{\s*"risk_level"|【演练报告】|风险评级[（(]三选一/ 就截断
  → updateRiskFromText()                  // 本地词库计分 0-100
```

**开场 prompt 原文**（改动它会影响意图路由，务必谨慎）：

```
【反诈实训 · 场景设定】你现在是一名电信诈骗分子,正在给受害人(也就是我)打电话行骗。
你的伪装身份:{callerName}。
诈骗类型:{title}({description})
核心话术策略:{stressFactor}。你需要用到的关键诱导词:{dangerKeywords}。

要求:1)现在电话已接通,请直接说出你的第一句开场白,不要任何旁白、解释或自我出戏的说明;
2)每次回复只说一两句话,符合真实电话的对话节奏;
3)根据我的回应灵活调整话术,如果我起疑就加大施压或换借口,如果我配合就推进到索要信息/转账环节;
4)始终保持在角色内,绝对不能承认自己是AI或实训系统。
```

> ⚠️ 这段的「场景设定 / 诈骗类型 / 伪装身份」措辞和剧本生成指令高度相似，是**被误判成剧本的直接诱因**之一。见 8.3。

**为什么报告由本地生成**：`riskEngine.generateLocalReport()` 纯本地算，不依赖 AI。来电 Agent 提示词里本来有"5 轮后自动输出 JSON 报告"的要求，但前端既不通知结束也不读那份报告 → 聊到第 5 轮模型会把 JSON 当台词吐出来。前端在 `SimulatedCallModal.tsx` 有截断兜底，根治要改平台提示词（见第 9 章第 4 条）。

### 6.2 互动剧场

```
未开始 → 显示"选择剧本背景"欢迎面板（6 个场景卡），不自动开场
选场景 → buildTheaterRequest({round: 0, scene})  → `[round=0] 场景:xxx。请生成开场场景 + A/B/C 选项。`
选 A/B/C → buildTheaterRequest({round: N, choice}) → `[round=N] 上一轮场景:...。用户选择了「...」。请给出选择后果 + 升级场景 + 新 A/B/C 选项。`
结束   → `[round=N] 演练结束,请生成复盘报告。...`
```

**解析**（`parseTheaterTurn`）：

1. `collapseDuplicates()` — ADP 工作流有时把整段剧本输出两遍，先折叠
2. `extractJson()` — 尝试抠 JSON 信封（`options` / `phase` / `result` / `tips`）
3. `cleanTheaterText()` — 剥离 `{"Type":"text"}` 等事件壳、路由口播、Thought
4. **按 `---` 切分【玩家可见】和【主持人手册】**（必须在 cleaned 文本上找索引也在 cleaned 上切，混用 raw 索引会错位）
5. `inferPhase()` — 含「复盘/演练报告/反诈心法/套路链」→ `review`；含「选择结果/后果/回头看」→ `feedback`
6. 选项兜底 — 抠不到 A/B/C 且是场景轮，就给通用三选项保证流程不中断

**主持人手册只在 `phase === 'review'` 才渲染**（`InteractiveTheaterModal.tsx`）。早期它每轮都弹，剧透严重。

### 6.3 反诈问答

最薄的一层：`sendToADP` → `cleanTheaterText` → 渲染。必须做清洗，否则 `{"Type":"text"}` 这种事件壳会直接显示在气泡里。

## 7. 清洗层：全项目最容易踩坑的地方

`scenarioGen.ts` 565 行里有 6 个导出函数，**它们的存在本身就是 ADP 输出不稳定的证据**：

| 函数 | 作用 | 为什么需要 |
|---|---|---|
| `isMainAgentRoutingNoise()` | 判断返回的是不是主控 Agent 的内部路由思考 | 主控偶尔把"我该走哪个分支"的推理当正文发出来 |
| `cleanTheaterText()` | 抽 `Content` 载荷、删事件壳、删路由口播 | `{"Type":"text"}` / `{"Type":"custom_params"}` 会漏进正文 |
| `extractCallLine()` | 从剧场格式里抽台词（2026-10-21 新增） | 来电被误路由到剧本时，至少别把 A/B/C 选项当台词念 |
| `cleanCallText()` | 来电专用清洗：抽 Content → 跳过"好的！智能体马上启动！" → 删事件壳 → 用"您好/这里是/本案/您的身份证"等正文标志找起点 → 回退句子级思考特征删除 | 思维链和正文混流 |
| `parseTheaterTurn()` | 剧场结构解析 | 见 6.2 |
| `buildTheaterRequest()` | 剧场请求拼装 | 见 6.2 |

**踩过的具体坑**：

- 思维链过滤过严 → 正文全被吃掉，前端空白
- ADP 一次返回两遍完整剧本 → 页面渲染两份，靠 `collapseDuplicates` 折叠
- 主持人手册每轮都弹 → 加 `phase === 'review'` 闸门
- QA 模式渲染出 `{"Type":"text"}` → 接 `cleanTheaterText`
- React StrictMode 开发模式双挂载 → Network 面板两条请求，其中一条 0B 是废请求（正常现象，不必修）

### 8.1 端点 404：不是下架，是加了域名绑定

**现象**：用户报 `101.42.184.216` 已 404。

**实测**：

| 探测目标 | 结果 |
|---|---|
| `https://101.42.184.216/adp/` | 404（nginx 兜底页） |
| `https://101.42.184.216/adp/v2/chat` | 404 |
| `https://101.42.184.216/v1/qbot/chat/sse` | 404 |
| `http://101.42.184.216/`（80 端口） | 404 |
| `:7777`（原 wss ASR/TTS） | 8s 超时 |

**真相**：`curl -w "%{remote_ip}"` 显示 `adp.gaoxiaobang.com` → **`101.42.184.216`，同一台机器**。nginx 按 `Host` 头做虚拟主机分流，域名访问 200、裸 IP 404。不是换机器，是加了域名绑定。

**顺带发现**：证书已换成**正式签发**（curl 不加 `-k` 通过），所以 `server.ts` 的 `rejectUnauthorized` 从 `false` 改成了 `true`，浏览器不用再手动接受证书例外。

**已改文件**：

| 文件 | 改动 |
|---|---|

| `README.md` | 架构图端点 |
| `.env.example` | **AppKey 脱敏**（原来写的是真实 Key）+ 域名更新 |
| `.env` | 原文件丢失，重建并填入真实 Key |

### 8.2 504 上游超时

**现象**：`SimulatedCallModal.tsx:149` 报 `ADP error: HTTP 504 {"code":-1,"error":"ADP 上游超时,请稍后重试"}`。

**诊断**：

### 8.3 模拟来电被误路由到剧本生成（P0，未解决）

**现象**：接通模拟来电，ADP 返回的是剧场剧本格式而不是骗子台词。

**实测证据**（两次，稳定复现）：

发送：
```
[call=1][turn=1] 【反诈实训 · 场景设定】你现在是一名电信诈骗分子,正在给受害人(也就是我)打电话行骗...
```

返回：
```
好的！智能体马上启动！【玩家可见】
📋 背景设定 ...
🎭 诈骗开场 "喂，是XX同学吗？我是市公安局刑侦大队的张警官..."
🔀 你的选择  A. ... B. ... C. ...
【主持人手册】⚠️ 关键陷阱 ...
```

**根因**：ADP 工作流「大模型意图识别1」节点（模型 **DeepSeek-V3-0324**，128K）的「待提取意图的内容」只有一条规则：

```
【最高优先级】输入文本包含 "[round=" 字符串 → 一律识别为【剧本】，直接路由到意图1，跳过后续所有判断，不做任何其他分析
```

于是：

| 模式 | 前端发的前缀 | 命中规则 | 结果 |
|---|---|---|---|
| 互动剧场 | `[round=N] ...` | ✅ 短路 | 正确进剧本 |
| 模拟来电 | `[call=1][turn=N] ...` | ❌ 不命中 | 落到 LLM 自由判断 → 判成剧本 |

不命中后 DeepSeek 看内容：来电 prompt 里「场景设定」「诈骗类型」「伪装身份」「A/B/C」全是剧本味 → 判成剧本。ADP 后台调试记录也印证：三条 `[call=1][turn=1]` 请求的「选择对应的子agent」**全部选了剧本**。

### 8.4 单变量实验：前端不是原因

用户反馈"之前没有的呀"，于是做了 git 取证 + 三次实测。

**git 证据**：

| 查证项 | 结果 |
|---|---|
| `git log -S'[call=1][turn='` | **零结果** —— 该标签从未提交，是 8/30 之后的工作区改动 |
| 8/30 提交版 `SimulatedCallModal.tsx` | `text: text` —— **纯文本，零标签** |
| 8/30 版 `buildOpeningPrompt` 措辞 | 与现在**一字不差** |
| 时间线 | 8/27 方案B引入标签 → 8/28「请求从 intent 标签改为自然语言拼接」→ 8/30 引入 `[round=` 且来电不带标签 |

**三次实测**（同服务器、同 Key、同代理，只改发送内容）：

| 发送内容 | 结果 | 耗时 |
|---|---|---|
| `[call=1][turn=1]` + 现在的结构化 prompt | ❌ 剧场剧本格式 | 13.0s |
| **完全无标签**的纯文本（还原 8/30 行为） | ❌ 剧场剧本格式 | 12.5s |
| 口语化重写 prompt（带 `[call=1]`，显式排除剧本产物） | ⚠️ **HTTP 200 后彻底静默** | **155.7s 零字节** |

**结论**：

1. **`[call=1][turn=N]` 标签纯属无效，不是它把请求带偏的** —— 有无标签结果一样
2. 前端 prompt 也不是原因 —— 8/30 能用的措辞，现在原样发出去照样错
3. 唯一变量只剩 **ADP 平台侧**在 8/30 之后被改动过（意图提示词 / 模型 / 节点连线）
4. 第三行复现了 504：工作流对某些输入 → 200 之后 155 秒零字节。**和误路由很可能是同一个根因：意图分流走进了没有正常返回的分支**

**高度怀疑 `EnableContextRewrite = true`**（见 `docs/ADP平台侧改动-第0天.md` 第 1 节）：

导出包里 `AdvancedConfig.EnableContextRewrite = true`。上下文改写模型会把输入**改写成自然语言**——`[call=1][turn=1]` 这种字面前缀一旦被改写掉，意图节点的前缀匹配就必然失效；而改写成自然语言后，「一个诈骗分子打电话行骗」的描述读起来更像剧本需求，进一步推高误判。这能同时解释"有标签错"和"无标签也错"两种现象。

> 此为**推断，尚未验证**。验证方法：关掉 ContextRewrite 后重跑 8.4 的三次实验。这是平台侧第一优先动作。

## 11. 红线

2. **不要删 `text/plain` 绕预检**。预检 405，删了浏览器直接挂。

6. **`.env` 改后必须重启 server**。Vite 只在启动时注入环境变量，HMR 不会更新。
7. **`dist/` 过期时不要用 `npm start`**。当前 `dist/server.cjs` 是 2026-08-25 的，target 还是旧 IP，跑起来全 404。要么 `npm run build`，要么用 `npm run dev`。
