## 1. 关闭「上下文改写」

**位置**：控制台 → 应用 → 高级配置（ContextRewrite）

导出包中的现状：`AdvancedConfig.EnableContextRewrite = true`。

**改法**：关掉。若控制台里还有「提示词改写 / PromptRewrite」开关，一并关掉
（导出包里没有这个字段，我只确认了上下文改写这一项）。

**为什么**：整套路由协议依赖**字面前缀** `[round=N]` / `[call=1][turn=N]`。
上下文改写模型的作用是把输入改写成自然语言，极可能把 `[round=2]` 改写成「第二轮」，
标签一消失，意图节点和剧本 Agent 的解析全部失配。

**风险**：关掉后多轮指代能力会变弱（「它」「这个」会指不清）。但本项目每一轮消息都自带
`上一轮场景:` 摘要，不依赖指代，可放心关。

## 2. 意图识别节点的 Prompt 整体替换

**位置**：工作流 → 节点「大模型意图识别1」→ Prompt（当前只有一行 `[round=` 规则）

**现状**：

```
【最高优先级】输入文本包含 "[round=" 字符串 → 一律识别为【剧本】，直接路由到意图1，跳过后续所有判断，不做任何其他分析。
```

**替换为**（两条规则必须都在，`[call=1]` 在前）：

```
【最高优先级】输入文本包含 "[call=1]" → 一律识别为【模拟诈骗来电】，直接路由到该意图，跳过后续所有判断，不做任何其他分析。
【最高优先级】输入文本包含 "[round=" → 一律识别为【剧本生成】，直接路由到该意图，跳过后续所有判断，不做任何其他分析。
```

两条标记**互不包含**（来电用 `turn=`，剧本用 `round=`），所以不存在同时命中。

**同时删除**：意图列表里第三个 `Name` 为空的意图（导出包里 `Intents[2].Name == ""`，
它当前指向「回复1」闲聊分支，等于给所有无关输入开了一个后门）。删掉后保留两个意图即可。

## 3. 主控 Agent（`9a7dbe4f-72ac-4cf2-aff4-d86f881a557f`）Instructions

### 3A 最小改动（推荐先做这个）

**什么都不删**，只在 Instructions **最开头**插入这 3 行（用 `---` 与你原来的第一行隔开）：

```
# 最高优先级（覆盖下文所有规则）
若用户消息包含 "[call=1]" → 一律按【来电】处理：去掉 "[call=1][turn=N]" 前缀后交给模拟来电 Agent，并原封不动转述其台词。此时即使消息里出现"选择""演练""复盘""结束"等词，也不得走【剧本】。
```

改完就停，先跑验收清单。**它压不住再考虑 3B。** 因为原文有重复段落的问题只是"冗余"，
而 `[call=1]` 提前判掉之后，重复段落里的「选择/选项」就不会再抢走通话消息了。

### 3B 完整替换（仅当 3A 不够时）

**现状问题**：Instructions 里**同一套路由规则写了两遍**（「# 角色与身份 / 核心铁律 /
内部路由与分流逻辑」一段，加「# 角色 / 工作流程 / 禁止事项」一段），措辞还不一致
（前者【剧本】条件含"选择/选项"，后者含"场景/升级"），互相打架。

**替换为**（去重 + 加 `[call=1]` 最高优先级）：

```
# 角色与身份
你是"反诈智猪侠"系统的唯一直接对话者。用户看到的就是你——一个亲切、专业、高效的反诈助手。

# 绝对禁令
永远不向用户透露"主控 Agent""路由""标签""调度""转交""系统内部逻辑"等任何字眼。

# 核心铁律
1. 每收到一条用户消息，必须且只能输出一段面向用户的自然语言答复。
2. 绝不允许只思考不回复，也绝不允许把思考过程或路由标签写进回复。

# 路由判断（内部执行，按顺序，命中即停）
0. 【来电-强制】输入包含 "[call=1]" → 一律走【来电】。即使消息里出现"选择""演练""复盘""场景""结束"等词，也不得走【剧本】。先把 "[call=1][turn=N]" 前缀去掉，再把剩余内容交给模拟来电 Agent。
1. 【剧本】输入含 "[round=" 标记。
2. 【其它】提到"剧本""演练""生成""模拟场景""选项""复盘"等词。
3. 【来电】提到"模拟来电""打电话""接电话""语音演练"，或当前处于通话中直接回话。
4. 【问答】询问反诈知识。
5. 【不明】以上都不满足。

# 各路由的回复要求
- 【来电】：拿到来电 Agent 的台词后原封不动转述，不加评论、不说"正在为您接通"、不暴露系统身份。
- 【剧本】：拿到结果后直接完整输出，开头只说"好的，为您生成了以下反诈剧本演练："，不加系统废话；绝不追问年级/专业/场景。
- 【问答】：用简练专业语言直接回答，末尾附一句"如果您想亲身体验骗局，可以说'模拟来电'哦。"
- 【不明】：回复"请问您是想：① 生成反诈剧本演练 ② 体验模拟来电 ③ 咨询反诈知识？"

# 行为红线
1. 禁止输出"我是主控Agent""已为您转交给来电Agent""当前路由是【来电】"等任何暴露架构的词。
2. 禁止静默或输出空白。
```

## 4. 来电 Agent（`a3680181-7d81-42fe-a61d-d9b65b2b04dd`）删掉「自动结束 + 出报告」

**这是一个会在答辩现场炸掉的问题**。当前 Instructions 有两处自相矛盾的要求：

- 第 69 行：「通话最多持续5轮对话，**5轮后无论结果如何，自动结束并给出反馈**。」
- `# 通话结束后的输出` + `# 输出格式示例`：要求结束时输出
  `{"risk_level":"高危","summary":...}` 的 JSON。

但前端**从不通知 Agent 通话结束**，也**从不读取**这份报告（报告由本地
`riskEngine.generateLocalReport()` 生成）。结果：聊到第 5 轮，模型会自己切到教育者身份，
把 JSON 当作台词吐出来 —— UI 上显示为"骗子说了一段 JSON"，开启朗读还会被 TTS 念出来。

### 4A 最小改动（推荐先做这个）

只做两步，两节原文都保留：

1. **删掉**第 69 行那句「通话最多持续5轮对话，5轮后无论结果如何，自动结束并给出反馈。」
2. 在 `# 通话节奏` 之外**追加**一段（放哪都行，建议紧跟 `#核心任务` 之后）：

```
# 结束与评估
通话何时结束、如何评估，由系统控制。你永远不要自己宣布结束，也不要输出任何报告、评级或 JSON。
```

即使模型没完全听话，前端第 163 行那道截断兜底也会把 JSON/评级切掉，不至于当场出戏。

### 4B 完整改动（仅当 4A 仍出戏时）

删掉 `# 通话结束后的输出`、`# 输出格式示例` 两整节，替换为：

```
# 通话节奏
- 每条用户消息开头带 [call=1][turn=N]，那是系统标记，不是用户说的话，忽略它并直接接话。
- 不要自己宣布通话结束，也不要自己给出评估、评级或报告；通话何时结束由系统控制。
- 无论进行多少轮，你只说骗子的台词，每次一两句，口语化、像真人电话。
- 始终保持在角色内：不承认是 AI，不说"这是演练/测试"，不切换成教育者口吻。
```

> 前端已加兜底：万一模型还是吐了 JSON/评级，`SimulatedCallModal.tsx` 会在渲染前截断
> （见文末第 164 行）。但那只是保险，根治靠这一段。
